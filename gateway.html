System Architecture Blueprint

Precision Layout for Engineering Implementation

L1. Entry Point
External Traffic
User Request / DNS / LB

Layer 1. Entry Layer (진입로)

역할: 클라이언트의 최초 접속을 수락하고 보안 필터링을 수행합니다.

핵심 기술: DNS, Global Load Balancer(L4), WAF(Web Application Firewall)

설명: 사용자의 요청이 네트워크를 통해 게이트웨이 시스템으로 들어오는 단계입니다. 이 레이어에서는 DDoS 방어 및 IP 화이트리스팅과 같은 기본적인 네트워크 보안이 처리됩니다.

L2. Data Plane
Traffic Engine
OpenResty Node
Lua Dynamic Processor

Layer 2. Data Plane (트래픽 처리 레이어)

역할: 모든 요청에 대해 실시간으로 비즈니스 로직(인증, 라우팅, 유량 제어)을 적용합니다.

핵심 기술: OpenResty, LuaJIT, lua-resty-core

상세 프로세스:

  • SSL Handshake: Redis에서 도메인에 맞는 인증서를 가져와 즉시 적용
  • Access Control: API Key 검증 및 SSO 세션 토큰 유효성 확인
  • Traffic Control: Rate Limiting 알고리즘을 통한 서비스 보호
  • Dynamic Proxy: 요청된 Host/Path에 따라 목적지 서버 결정
L3. Control Plane
Admin API & UI
Policy & Config Manager

Layer 3. Control Plane (관리 레이어)

역할: 시스템 운영자가 게이트웨이의 동작 방식을 정의하고 명령을 내립니다.

핵심 기술: React (Front), Node.js/Go (Back), RESTful API

설명: 설정 변경(예: 서버 추가, 유량 제한 변경 등)이 여기서 일어나며, 변경사항은 즉시 Layer 4에 저장됩니다.

L4. State Store
Redis Cluster
Single Source of Truth

Layer 4. State Store (상태 저장 레이어)

역할: 게이트웨이 시스템의 "단일 진실 공급원(Single Source of Truth)"입니다.

핵심 기술: Redis (Sentinel/Cluster 모드)

설명: 설정 데이터(라우팅 테이블, SSL 인증서)와 동적 데이터(Rate Limit 카운터, 활성 세션)를 저장합니다. 인메모리 방식이므로 Layer 2에서 극도로 빠르게 접근할 수 있습니다.

L5. Upstream Layer
Application Services
Service A
Authentication / Profile
Service B
Transaction / Order
Service C
Inventory / Logistics

Layer 5. Upstream Layer (실제 서비스 레이어)

역할: 비즈니스 로직을 실제로 수행하는 백엔드 서버들입니다.

핵심 기술: 마이크로서비스(MSA), 컨테이너(K8s), 레거시 API 서버 등

설명: 게이트웨이는 이 레이어에 있는 서버들이 몇 대인지, 어디에 있는지(IP) 상관없이 동적으로 트래픽을 전달합니다.

L6. Insights Layer
Observability Plane
Prometheus
Time-series Metrics
Grafana
Insight Dashboards

Layer 6. Observability Plane (인사이트 레이어)

역할: 시스템에서 발생하는 모든 현상을 데이터로 기록하고 시각화합니다.

핵심 기술: Prometheus, Grafana, ELK Stack

추적 지표:

  • Metrics: RPS(초당 요청수), Latency(응답 지연), Error Rate(에러율)
  • Logging: 개별 요청의 상세 이력(Request ID 기반 추적)
  • Health: 업스트림 서버들의 가용 상태(Up/Down) 실시간 모니터링

Data Plane (L2)

트래픽의 실질적 처리부. 모든 요청에 대해 Lua 스크립트가 실행되어 보안 검증 및 라우팅을 1ms 내에 수행합니다.

Control Plane (L3)

관리 도구. 개발자나 운영자가 웹 UI를 통해 설정을 변경하면 이 레이어가 Redis에 데이터를 즉시 동기화합니다.

State Store (L4)

상태 저장소. 시스템 전체의 설정값, SSL 인증서 원본, 실시간 유량 제한 카운터 등이 중앙 집중적으로 관리됩니다.

Observability (L6)

전체 시스템 감시. 트래픽의 성공률, 지연 시간, 에러 로그를 수집하여 시스템의 건강 상태를 투명하게 보여줍니다.
